# H3 configuration and verification

## Client and service boundary

Play2Evolve's `local` backend submits video jobs to an external H3-compatible
HTTP service. The service loads the model and performs inference. The asset
worker submits requests, downloads MP4 files, and extracts/composites frames.
Codex authentication and video-service access are separate configurations.

This release does **not** bundle H3 weights, SGLang patches, CUDA environments,
or a verified public deployment command. Use an independently configured service
that implements the API below. Naming a service “SGLang” is not sufficient to
establish compatibility. A reproducible public server deployment recipe remains
on the release checklist; this client guide does not replace it.

GPU placement, tensor/sequence parallelism and CPU offload are controlled by the
service deployment. `--asset-parallelism` controls client jobs, not GPU workers.
To verify eight-card inference, inspect the server's worker/rank configuration
and GPU activity **during a real generation**. GPU utilization alone can include
unrelated jobs and does not prove which workers executed this request.

The video worker itself does not load GPU weights with this HTTP backend.
However, the retained Craft Bootstrap preflight still invokes `nvidia-smi` on
the execution host. A GPU-less client-only Bootstrap deployment is not fully
supported by that inherited preflight yet; merely setting a remote URL does not
remove this dependency.

## Configure on the execution host

```bash
export H3_BACKEND=local
export H3_URL=http://127.0.0.1:30010
export GAMECRAFT_H3_JOB_TIMEOUT_SECONDS=3600
export GAMECRAFT_ASSET_PYTHON="$(command -v python)"
```

Use a base URL without `/v1` or a trailing slash. When the service runs elsewhere,
replace the host with an address reachable from the actual worker. The local
HTTP adapter intentionally bypasses `http_proxy`/`https_proxy` and does not attach
an authorization header. A hosted provider requiring a different API or access
mechanism needs an adapter; a URL substitution alone is insufficient.

Set these variables before starting a process: `gen_assets.H3_URL` is initialized
when the module is imported. For Craft Initialization, pass
`--h3-backend local --h3-url "$H3_URL"` to `initialization prepare`; the resulting
`session.json` freezes those settings for `run`. Later environment changes do not
rewrite an already-prepared session. Refinement and Evolution read `H3_URL` from
their process environment and accept `--h3-backend`.

For GameASG, explicitly supply `--h3-url "$H3_URL" --h3-timeout 3600` in the shared
arguments for all stages. Its worker sets `H3_BACKEND=local` and translates the
timeout into `GAMECRAFT_H3_JOB_TIMEOUT_SECONDS`. The asset Python must have this
package installed; the browser container is not the H3 inference server.

## Required API

| Endpoint | Expected behavior |
| --- | --- |
| `GET /health` | Service health response; useful for setup checks. |
| `GET /v1/videos` | Job list used by Craft preflight: a list, or an object with a `data` or `videos` list. |
| `POST /v1/videos` | Accept the generation JSON and return an object containing `id`. |
| `GET /v1/videos/{id}` | JSON job status; worker polls until `completed` or `failed`. |
| `GET /v1/videos/{id}/content` | Return the completed MP4 bytes. |

A text-to-video request has `task: "t2va"`, `prompt`, `seed`, empty `conditions`,
`seconds`, and `target` with `short_edge`, `aspect_ratio`, `duration_seconds`.
The existing client commonly requests a 768-pixel short edge and 4 seconds.
The service must support the task, sizes and durations requested by the plan.

Conditioned requests use `task: "fl2va"`. Image conditions contain `type: "image"`,
`uri`, `role: "keyframe"`, and `frame_index` (0 or -1). The current local client
can pass **absolute file paths** in `uri`; it does not upload those images. The
server must see the files at the same paths, typically through a shared mount.
A successful text-to-video smoke test does not validate that conditioned path.

Craft Bootstrap can reject preflight when there are existing training/H3 jobs.
`--allow-shared-services` together with `--bootstrap-only` explicitly permits
sharing an already-running service. It does not start, stop, or reconfigure it.

## Generate one smoke-test clip

First check connectivity from the asset worker's host:

```bash
curl --noproxy '*' --fail --max-time 10 "$H3_URL/health"
curl --noproxy '*' --fail --max-time 10 "$H3_URL/v1/videos"
```

The following submits **one real generation request** and writes a new clip.
It uses the same HTTP transport as the pipeline. It refuses to overwrite an
existing result; choose another filename for a repeat test.

```bash
export H3_TIMEOUT=3600  # Direct transport smoke test only; see timeout notes below.
python - <<'PY'
from pathlib import Path
from time import monotonic
from gen_assets import h3_t2va

output = Path('outputs/h3-smoke/lake.mp4')
if output.exists():
    raise SystemExit('Output exists; choose a fresh smoke-test filename.')
output.parent.mkdir(parents=True, exist_ok=True)
start = monotonic()
h3_t2va('A calm illustrated mountain lake, gentle water ripples, fixed camera, no text.',
        1001, str(output), aspect='16:9', seconds=4)
print(f'Saved {output}; elapsed {monotonic() - start:.1f} seconds')
PY
ffprobe -v error -select_streams v:0 \
  -show_entries stream=width,height,codec_name:format=duration \
  -of json outputs/h3-smoke/lake.mp4
```

Watch the clip as well. An HTTP 200 or valid MP4 alone does not demonstrate visual
quality, loop continuity, correct keyframe handling, or the requested GPU count.

## Timeouts, steps and concurrency

| Control | Retained implementation |
| --- | --- |
| `GAMECRAFT_H3_JOB_TIMEOUT_SECONDS` | Effective Craft material polling budget; default 1200 seconds. Includes time queued at the service. |
| `H3_TIMEOUT` | Direct `gen_assets` transport timeout; default 600 seconds. The normal material worker overwrites it using the setting above. |
| GameASG `--h3-timeout` | Default 3600 seconds; passed to the material worker and used to bound its subprocess. |
| `GAMECRAFT_H3_OOM_WAIT_SECONDS` | OOM retry window; default 600 seconds. |
| `GAMECRAFT_H3_OOM_RETRY_SECONDS` | Delay between recognized OOM retries; default 30 seconds. |

An already-submitted pending job is polled. A recognized OOM failure can cause
resubmission under the inherited retry policy. Client timeout is not server-side
cancellation. Inspect server jobs before manually resubmitting a failed run.
`--asset-candidates 1` does not disable technical retries or later agent requests.
The client also uses a lock under its temporary directory; differing `TMPDIR`
values do not share that lock, so server-side queuing still matters.

For the documented setup, configure the server default to **50 inference steps**.
Craft's normal `h3_t2va`/`h3_fl2va` calls do not include `num_inference_steps`.
In GameASG, `--h3-steps 50` retains this behavior; a nondefault value overrides
text-to-video requests, not every conditioned request. Inspect effective service
configuration and request logs to establish the actual inference settings.

## Troubleshooting and other adapters

- Connection refused: verify the service is running and the URL refers to the
  execution host you intended. `localhost` is not shared across machines.
- HTTP 404 or unexpected fields: check the endpoint/schema contract above.
- Long pending time: inspect the service's queue and workers; use the effective
  job timeout, not only `H3_TIMEOUT`, for pipeline runs.
- Missing conditioning image: check the service's mount/path visibility.
- OOM: inspect GPU memory and server logs; restarting a client does not free
  unrelated allocations or change the model's parallel configuration.

The copied Craft adapters also support `minimax` and `wan`; these are distinct
backends, not alternative URLs for `local`. MiniMax reads `MINIMAX_API_KEY` from
the environment; Wan needs its own local runtime/weights. Those providers and
their current capabilities are not validated by this H3 service smoke test.
